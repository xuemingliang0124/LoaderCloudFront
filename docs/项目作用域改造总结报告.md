# 项目作用域改造总结报告

## 一、改造背景

后端更新了项目管理与用户权限模型，核心变更包括：
1. **资源接口项目作用域化**：脚本/场景/运行/定时接口全部改为 `/projects/{pid}/...` 嵌套路由
2. **权限模型**：引入全局角色（admin/user）+ 项目成员角色（owner/editor/viewer）双层体系
3. **新增接口**：项目 CRUD、项目成员管理、用户管理 CRUD、场景/项目删除预检

前端需同步改造以对齐后端契约。

## 四、架构设计决策

### 决策 1：路由采用项目作用域嵌套路由

```
/projects                              项目列表（全局入口）
/projects/:projectId/members           项目成员管理
/projects/:projectId/scripts           脚本列表
/projects/:projectId/scenarios         场景列表
/projects/:projectId/scenarios/create  新建场景
/projects/:projectId/runs              运行记录
/projects/:projectId/runs/:runNo       运行详情
/projects/:projectId/schedules         定时任务
/agents                                压力机（全局资源，不挂项目）
/users                                 用户管理（仅 admin）
```

`projectId` 来自 URL 路由参数，刷新不丢失、可分享链接、路由守卫统一校验。

### 决策 2：project_id 由页面从 `route.params` 取，API 函数首参接收

不隐式塞 store，避免「切换项目后 API 仍打旧项目」的时序 bug。

### 决策 3：权限只做 UI 收敛，后端是唯一授权门禁

前端按 `my_role` 隐藏写操作按钮，但不能阻止直接调 API——后端 `ensure_project_access` 兜底。

### 决策 4：角色中文化

项目角色「项目管理员/编辑者/观察者」、全局角色「管理员/普通用户」，与后端 API 收/出口径完全一致，前端不做转换。

### 决策 5：拦截器精准跳转

只对 `3021`（项目不存在）/ `3030`（非成员）跳项目列表；`3031`（角色不足）/ `1010`（非管理员）仅提示留当前页，避免误跳打断操作。

## 七、改造总结

本次改造将前端从「扁平资源模型」完整迁移到「项目作用域 + 双层权限模型」，覆盖了路由、API、类型、Store、布局、页面、拦截器全链路。改造后：

1. **数据隔离**：用户只能看到自己有权限的项目及其资源
2. **权限收敛**：观察者无法看到写操作入口，编辑者以上可操作资源，项目管理员可管理成员
3. **用户体验**：项目切换器 + 路由嵌套使导航自然流畅，刷新不丢失上下文
4. **安全兜底**：前端只做 UI 收敛，后端 `ensure_project_access` 是唯一授权门禁
5. **可维护性**：统一模式（`projectId` 首参 + `canWrite` computed），新增资源页可快速复制
